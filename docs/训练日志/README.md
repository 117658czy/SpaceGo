# 训练日志（原始记录）

本目录保存 ELO 门控在线训练的**原始控制台输出**，供逐行核对 README、
[成果说明](../技术文档/成果说明.md) 与 [训练日志总结](../技术文档/训练日志总结.md) 中引用的数字。

训练日志本身是纯文本，未经剪辑：包含启动横幅、每轮对弈结果、逐局损失、门控诊断、
KataGo 评估标尺值与接受/回滚判定。日志中的绝对路径是原训练机的路径，换机器复现时
目录结构不同属正常现象。

> 权重文件（`*.pt`，单个约 237 MB）不随仓库分发，因此这里只能核对**训练过程与评估结果**，
> 无法直接复跑某一轮的权重。

## 二、逐行核对

所有被引用的数字都能用一条命令重新算出来。

Windows PowerShell：

```powershell
# 取出所有 KataGo 评估行（目差与单局耗时）
Select-String -Path .\训练日志\*.txt -Pattern '评估1局 vs KataGo' -Encoding UTF8

# 只算目差
Select-String -Path .\训练日志\*.txt -Pattern '目差=(-?[0-9.]+)目' -Encoding UTF8 |
  ForEach-Object { [double]$_.Matches[0].Groups[1].Value } | Measure-Object -Min -Max -Average

# 只算单局耗时
Select-String -Path .\训练日志\*.txt -Pattern '耗时=([0-9]+)s' -Encoding UTF8 |
  ForEach-Object { [double]$_.Matches[0].Groups[1].Value } | Measure-Object -Min -Max
```

Linux / macOS：

```bash
grep -h '评估1局 vs KataGo' 训练日志/*.txt
grep -ho '目差=-\?[0-9.]*目' 训练日志/*.txt | sort | uniq -c
```

## 三、汇总统计（据本目录 5 个文件实测）

| 指标 | 样本 | 结果 |
|------|------|------|
| KataGo 目差（标尺值） | 8 次评估 | 区间 **−366.5 ~ −349.5 目**，最优 −349.5 |
| KataGo 评估单局耗时 | 13 次评估 | 区间 44 ~ 182 s，中位数 55 s |
| 自对弈单局耗时 | 36 局 | 区间 28.7 ~ 75.5 s，中位数 63.3 s |

> **口径说明（容易误读的地方）**
>
> 1. 日志里的 `耗时=` 是**一局棋的总耗时**（一局约 300 步），不是单步耗时。README 早期版本
>    把它写成「单步耗时 35–55 s」，属于口径错误，已更正为「单局耗时」。
> 2. `目差=` 是**单局**与 KataGo 的终局目差，不是多次对局的平均值；单局方差大，这也是
>    「评估信号过稀」问题的直接来源（见训练日志总结 §5.4）。
> 3. 不同文件的目差水平不同，因为它们属于不同实验轮次（缩放、噪声地板、长运行），
>    不应混在一起当作同一模型的稳定棋力。
> 4. 上述数字来自 5 个日志文件；作者本机还有更多未随仓库分发的历史日志，其样本量更大，
>    但本目录只公布仓库内可核对的这部分。

## 四、阅读日志时可能遇到的噪声

- `╔═╗` 横幅与 `[标记]` 行是训练器的阶段提示，不是错误。
- 门控诊断会把 8 个专家权重逐行打印，因此单次诊断会占 8 行。
- `train_out_broken_0913.txt` 中出现恒定的损失与恒定门控损失，是**故障现场**，属预期留存，
  用于对照修复后的正常运行。
- 日志为 UTF-8 编码，Windows 记事本若以 GBK 打开会出现中文乱码，用 VS Code 或
  `Get-Content -Encoding UTF8` 打开。
