SpaceGo 维空弈是从零实现的 AlphaZero 式围棋引擎：HMGS-DP 搜索 × CA-MOE 8 专家网络（约 6200 万参数）× 可复现训练闭环。位棋盘、推理、训练、GTP、GUI 全部自研。 SpaceGo is an AlphaZero-style Go engine written from scratch: HMGS-DP search × an 8-expert CA-MOE network (~62M parameters) × a reproducible training loop. Bitboards, inference, training, GTP and GUI are all hand-written.

01 / Positioning

不是调参脚本，是一整套引擎栈Not a tuning script — a full engine stack

大多数开源围棋项目止步于“训练一个网络”。SpaceGo 把工程链路也补齐了：棋盘、搜索、推理、训练、协议、界面、测试，每一层都能单独拆出来读。 Most open-source Go projects stop at "train a network". SpaceGo also ships the engineering chain: board, search, inference, training, protocol, GUI and tests — each layer readable on its own.

01两套自研算法Two original algorithms

搜索侧 HMGS-DP（换位表 DAG 合并 + 多样性保护），推理侧 CA-MOE（共享主干 + 8 专家头 + 风格门控），通过评估器注入解耦，可独立替换与压测。 HMGS-DP on the search side (transposition-table DAG merging + diversity protection), CA-MOE on the inference side (shared trunk + 8 expert heads + style gating). Decoupled via evaluator injection.

02可复现训练闭环Reproducible training loop

自对弈 → 经验回放 → 门控接受/回滚 → KataGo 目差评估 → 教师蒸馏。日志与检查点格式完整保留，数字都能回查。 Self-play → replay → gated accept/rollback → KataGo score-gap evaluation → teacher distillation. Logs and checkpoint formats are preserved, so every number is auditable.

03工程而不只是论文Engineering, not a paper

CMake 可裁剪构建（CUDA / LibTorch / 训练 / GUI / 测试独立开关）、失败自动降级、跨平台抽象、中文注释与 17 篇算法文档。 Trimmed CMake builds (CUDA / LibTorch / training / GUI / tests toggled independently), graceful fallbacks, cross-platform abstraction, Chinese comments and 17 algorithm documents.

04诚实的基准Honest benchmarks

仓库同时记录“做到了什么”和“还差什么”，包括 −349.5 目的对 KataGo 差距。不用“工业级棋力”做宣传。 The repo records both what works and what doesn't — including the −349.5 point gap against KataGo. No "industrial strength" marketing claims.

03 / Algorithms

HMGS-DP × CA-MOEHMGS-DP × CA-MOE

HMGS-DP：分层合并图搜索HMGS-DP: merged graph search

以 Zobrist 哈希为键建立换位表，相同局面直接复用节点，搜索结构由树变成 DAG，同一局面只评估一次。已提供虚拟损失与工作窃取队列的骨架，但 GTP 主循环当前仍是单线程批量实现。 A Zobrist-keyed transposition table reuses nodes for identical positions, turning the search tree into a DAG so each position is evaluated once. Virtual loss and work-stealing skeletons exist, but the GTP loop is still a single-threaded batched loop. 

UCT(i) = Q(i) + C · P(i) · √(ln N / n_i)

tt_ : unordered_map<uint64_t, HMGS_Node*>

CA-MOE：因果感知混合专家CA-MOE: causal-aware MoE

共享主干（10 残差块 / 256 通道）只算一次，8 组策略头与价值头并行输出；5 维对手棋风向量经零初始化投影叠加为门控偏置，让“按对手风格选专家”成为可学习机制。 A shared trunk (10 residual blocks / 256 channels) runs once; 8 policy heads and 8 value heads run in parallel. A 5-dim opponent-style vector, zero-initialised, biases the gate — making expert selection style-conditioned and learnable. 

w       = softmax(Gating(features) + style_projection(opponent_style))
policy  = Σ_e  w_e · policy_e
value   = Σ_e  w_e · value_e

05 / Quick start

五分钟内跑起来Up and running in five minutes

不装 CUDA、不装 LibTorch 也能编译出规则引擎主体；要跑神经网络再补上 LibTorch 2.6.0+cu124。 You can build the rule-based engine without CUDA or LibTorch; add LibTorch 2.6.0+cu124 only for neural inference.

Windows · 完整构建 
git clone https://github.com/117658czy/SpaceGo.git
cd SpaceGo

cmake -S . -B build -G "Visual Studio 17 2022" -A x64 `
      -DLIBTORCH_ROOT="D:/libtorch-win-shared-with-deps-2.6.0+cu124/libtorch"
cmake --build build --config Release

# 产物 / outputs: build/Release/spacego.exe, spacego_train.exe, SpaceGo_GUI.exe
最小构建 · 只需要编译器 
cmake -S . -B build -DUSE_CUDA=OFF -DUSE_LIBTORCH=OFF -DBUILD_TRAIN=OFF -DBUILD_GUI=OFF
cmake --build build --config Release

# 启动 GTP
.\spacego.exe --gtp --simulations=1600
