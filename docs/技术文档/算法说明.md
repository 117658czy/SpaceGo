# SpaceGo 维空弈 算法说明

本文档描述开源版本中**实际保留并编译**的算法实现。文中提到的所有类与文件均可在本仓库中找到。

---

## 一、系统概述与数据流

SpaceGo 是一个 AlphaZero 式的围棋 AI：搜索提供着法，神经网络提供先验与价值，二者交替迭代。

```
          棋盘状态
             │
   ┌─────────┴──────────┐
   │  感知层（位棋盘 + CUDA）  │  GoBoardCPU / GoBoardCUDA
   └─────────┬──────────┘
             │ 策略先验 P + 价值 V
   ┌─────────┴──────────┐
   │  推理层（CA-MOE 混合专家） │  CA_MOEExpertSystem
   └─────────┬──────────┘
             │ 注入评估器
   ┌─────────┴──────────┐
   │  决策层（HMGS-DP 搜索）   │  HMGSDP_Optimized
   └─────────┬──────────┘
             │ 访问次数分布 π
   ┌─────────┴──────────┐
   │  训练（自对弈 + 门控）    │  EloGated / Diploid / Unsupervised
   └────────────────────┘
```

- GTP 与交互式入口由 `GoEngine`（[go_engine.h](file:///e:/SpaceGo%20维空弈/opensource/include/go/engine/go_engine.h)）封装，`--model` 指定模型后走神经网络引擎，否则回退到规则/搜索评估。
- 训练入口为 `spacego_train`（[train_main.cpp](file:///e:/SpaceGo 维空弈/opensource/src/train_main.cpp)）。

## 二、感知层：位棋盘与 CUDA 加速

### 2.1 位棋盘表示

19×19 = 361 个交叉点，用 `6 × uint64_t` 位图表示（`BITBOARD_WORDS = (361+63)/64 = 6`），黑白各一份：

```cpp
uint64_t black_bits_[6];
uint64_t white_bits_[6];
```

位运算即可完成：落子/提子的位图更新、气与连通块的洪泛、合法着法筛选、自杀/打劫判断。相比逐点数组，位棋盘让气计算与连通性判断的常数因子显著降低。

### 2.2 Zobrist 哈希

`include/go/board/zobrist_hash.h` 提供 Zobrist 哈希：每个 (坐标, 颜色) 预生成随机数，棋盘哈希 = 所有棋子随机数的异或，并叠加**行棋方**分量。哈希用于：

- 换位表（transposition table）键，实现相同局面合并；
- 自对弈经验去重与缓存。

### 2.3 CUDA 内核

`src/perception/cuda/go_board_kernels.cu` 提供批量内核入口，由 `GoBoardCUDA` 调用。
**当前状态：接口占位。** `batch_calculate_liberties_kernel` 将气数固定写 0，
`batch_check_legal_moves_kernel` 只判空点（未判自杀/劫），`batch_generate_legal_moves_kernel`
只收集空点；文档早期版本提到的 `batch_play_move` / `batch_undo` / `batch_board_to_features`
在 `.cu` 中并不存在。GTP 推理主链路未实例化 `GoBoardCUDA`，实际棋盘运算走 CPU 位棋盘；
神经网络前向由 LibTorch 使用 CUDA（若可用）。

| 内核 | 当前实现 |
|------|---------|
| `batch_generate_legal_moves` | 收集空点（未排除自杀/劫） |
| `batch_calculate_liberties` | 固定返回 0（占位） |
| `batch_check_legal_moves` | 仅判空点 |

内存布局采用 `struct-of-arrays`（所有棋盘的 black_bits 连续、white_bits 连续），
批量大小取 2 的幂（64/128/256）以提升占用率。该层是后续把棋盘计算迁移到 GPU 的接口骨架，
不应被视为已生效的 GPU 加速。

特征平面接口为 17 通道，但 `encode_to_tensor()` **当前只填充前 3 个平面**
（黑、白、行棋方），其余通道恒为 0，供 `CA_MOEExpertSystem` 作输入；训练与推理使用同一约定。

## 三、决策层：HMGS-DP 搜索

**HMGS-DP = Hierarchical Merged Graph Search with Diversity Protection（分层合并图搜索与多样性保护）**。

核心实现分三层，从底到上：

| 层次 | 头文件 | 职责 |
|------|--------|------|
| 算法核心（门面 + 组件） | `include/network/algorithms/` | 节点、UCT、相似度、合并网络、持久化 |
| 并行优化实现 | `include/go/search/hmgs_dp_optimized.h` | 多线程并行、批量推理、DAG 合并、统计 |
| CUDA 扩展 | `include/go/search/hmgs_dp_cuda.h` | GPU 批量搜索、拓扑加速器接入 |

### 3.1 节点与并行 UCT

节点结构 `HMGS_Node`（见 [hmgs_dp_optimized.h](file:///e:/SpaceGo 维空弈/opensource/include/go/search/hmgs_dp_optimized.h)）保存：着法坐标、先验概率 `prior_prob`、累计价值与访问次数（`std::atomic<int> visits`）、父指针与子节点、`zobrist_key`、虚拟损失 `virtual_loss`、合并计数与合并概率。

- **虚拟损失（virtual loss）**：节点结构已预留 `virtual_loss` 原子计数，用于并行线程
  暂时避开同一路径；但当前 `search()` 主循环是单线程批量实现，虚拟损失尚未接入选择/回传。
- **选择准则**：当前代码实际使用

  ```
  UCT(i) = Q(i) + C · √(ln(N+1) / (n_i+1))
  ```

  其中 `Q(i)` 为节点平均价值，`N` 为父节点访问数，`n_i` 为子节点访问数，
  `C` 为探索常数（默认 1.414）。神经网络先验 `prior_prob` 目前只用于展开时的
  **top-K 候选排序**（`expand_node_with_prior`），尚未乘入探索项；这与早期文档中的
  `C · P(i) · √(ln N / n_i)` 公式不一致，是待修复项。
- **价值方向**：`backpropagate()` 每向上一层翻转一次价值，使每个节点累计的是
  “该节点行棋方视角”的价值；因此父节点选择子节点时应取子节点价值的相反数。
  当前 `select_node_for_expansion()` 直接取正，属于已知 P0 缺陷（详见 README“已知限制”）。

### 3.2 换位表状态合并（DAG）

搜索树通过 `std::unordered_map<uint64_t, HMGS_Node*> tt_` 记录 `zobrist_key → 节点`。展开子节点时若哈希已存在，则通过 `add_child_ref` 复用既有节点，使搜索结构由树变为**有向无环图（DAG）**，相同局面只评估一次，避免重复神经网络推理。

换位表持有节点的全部所有权（DAG 下多父共享），析构时遍历哈希表统一释放，杜绝 double free。

### 3.3 神经网络评估注入

`HMGSDP_Optimized` 暴露两个评估器接口，使搜索与网络解耦：

```cpp
// 单节点路径：策略先验 + 价值
void set_neural_evaluator(PolicyPriorFn policy_fn, ValueFn value_fn);

// 批量路径（优先级更高，可显著提升 GPU 利用率）
void set_batch_evaluator(BatchEvaluatorFn eval_fn);
```

- 设置了**批量评估器**时，搜索主循环按 `batch_size` 收集若干叶子节点统一前向，再走 `expand_node_with_prior`；否则退回逐节点的 `expand_node` + `simulate`。
- 展开时对候选着法按先验做 top-K 截断（与批量路径共享逻辑），保留高先验窄分支，控制分支因子。
- `get_root_policy()` 返回根节点子节点的访问次数归一化分布，即自对弈训练目标 π；`get_root_value()` 返回根平均价值。

### 3.4 空间拓扑加速

`SpatialTopologyAccelerator`（[spatial_topology_accelerator.h](file:///e:/SpaceGo 维空弈/opensource/include/go/search/spatial_topology_accelerator.h)）批量计算空间拓扑特征：支持单棋盘 CPU 计算与批量计算，内部按任务规模在 CPU 多线程与 GPU 之间分片（异构模式），并由 `SpatialTopologyCalculator` 承载具体度量。`HMGSDP_CUDA` 通过 `set_topology_accelerator()` 接入，为搜索提供拓扑相关的加速与启发信息。

### 3.5 搜索引擎组件（门面模式）

`algorithms::HMGSDP`（[hmgs_dp.h](file:///e:/SpaceGo 维空弈/opensource/include/network/algorithms/hmgs_dp.h)）是**门面（Facade）**，职责限于生命周期与接口转发，实际功能委托给 `SearchEngine` 及以下专职组件：

```
network/algorithms/
├── search_engine.*          搜索主控（门面委托目标）
├── hmgs_node.*              搜索节点
├── calculation/
│   ├── uct_calculator.*         UCT 计算
│   ├── similarity_calculator.*  局面相似度
│   └── diversity_calculator.*   多样性度量
├── data/
│   ├── node_manager.*           节点池与生命周期
│   └── merge_network.*          合并网络（可合并节点间的关系图）
├── control/search_controller.*  搜索推进控制
├── execution/simulation_executor.* 模拟执行
├── config/  hmgs_config.h / config_manager.*  参数与配置
└── persistence/ data_exporter.* / data_importer.*  搜索树/合并网络/多样性图导出导入
```

其中：

- **相似度与合并**：`similarity_calculator` 给出局面相似度，`merge_network` 维护可合并关系，搜索据此在 DAG 上进一步合并语义相近节点；被合并节点记录 `merge_probability`。
- **多样性保护**：`diversity_calculator` 度量分支多样性；对长期未被合并、久未访问的分支给予额外探索资源，避免搜索过早收敛到单一变化。
- **持久化**：搜索树、合并网络、多样性图可导出/导入（含 v1 兼容接口），便于分析离线局面。

## 四、推理层：CA-MOE 混合专家元决策

**CA-MOE（Causal-Aware Mixture of Experts）** 是一个共享主干 + 多专家头 + 门控的结构（[ca_moe_expert.h](file:///e:/SpaceGo 维空弈/opensource/include/go/neural/ca_moe_expert.h)）。

### 4.1 结构

```
输入 17×19×19
   │
SharedBackbone（输入卷积 + 10 个残差块 + Dropout，通道 hidden_dim=256）
   │  共享特征
   ├── ExpertPolicyHead × 8   → 每个专家输出 362 维策略
   ├── ExpertValueHead  × 8   → 每个专家输出 1 维价值
   └── GatingNetwork
         fc1(hidden_dim×361 → 512) → fc2(512 → 8) → softmax
         + style_projection(5 → 8) 对手风格偏置
```

融合输出：

```
final_policy = Σ_e  w_e · policy_e
final_value  = Σ_e  w_e · value_e
```

其中 `w = softmax(logits)`，`logits = GatingNetwork(features) + style_projection(opponent_style)`。

### 4.2 门控分化与防坍缩

- **softmax 温度固定为 1.0**。历史上尝试过 >1 的温度软化，但 `softmax(x/T)` 的梯度含 `1/T`，会同比缩小所有门控梯度，反而削弱正则，导致门控坍缩为 one-hot（专家退化为单专家）。
- 防止坍缩依赖：门控 logits 的 **KL/负载均衡正则**（权重较大）+ **Dropout** + 训练时对门控 logits 施加 L2。
- `forward_with_logits()` 同时返回权重与 logits，供训练阶段对 logits 施加正则。

### 4.3 对手风格条件化

`set_opponent_style()` 注入 5 维对手风格向量 `[攻击, 防守, 均衡, 实地, 厚势]`，经零初始化的 `style_projection` 叠加为门控偏置，实现"看对手下棋"的专家条件分化：

- 权重零初始化 → 初始无偏置，不破坏已有棋力；
- 训练时注入多样化风格（原型池采样）迫使门控学习"风格 → 专家"映射；
- 未设置时行为与无条件门控完全一致（兼容旧 checkpoint 与自对弈）。
- `load_compat()` 逐组件 try_read 加载，旧 checkpoint 缺少 `style_projection` 时保持零初始化。

### 4.4 训练损失

总损失由三部分组成：

```
L = w_policy · L_policy + w_value · L_value + w_gating · L_gating
```

- `L_policy`：策略交叉熵（目标为搜索访问分布 π）；
- `L_value`：价值均方误差（目标为对局结果 z）；
- `L_gating`：门控正则（负载均衡 / KL），惩罚专家坍缩。

权重由 `ParamRegistry` 载入，可通过 `spacego --auto-tune` 自拟合搜索（见自拟合调参报告：策略权重下调、价值权重上调可显著降低总损失）。

## 五、异构计算与负载均衡

`include/go/heterogeneous/` 提供 CPU/GPU 协同的通用设施：

| 组件 | 职责 |
|------|------|
| `workload_analyzer` | 分析任务规模与特征，判断适合 CPU 还是 GPU |
| `task_decomposer` | 将大任务切分为可并行子任务 |
| `device_load_balancer` | 采样设备负载（CPU：`GetSystemTimes` / `/proc/stat`；GPU：NVML），EMA 平滑后动态调整 CPU/GPU 分配比例，过载时分流/回流 |
| `heterogeneous_compute_engine` | 统一调度 CPU 线程池与 CUDA 流 |
| `result_merger` | 合并多设备计算结果并保持顺序一致 |

`DeviceLoadBalancer` 的 NVML 调用由 `SPACEGO_CUDA_ENABLED` 控制（随 `USE_CUDA` 开启），NVML 初始化失败时自动回退到基于队列深度的启发式利用率估算，不阻断运行。

## 六、训练算法

训练入口 `spacego_train`，共四种模式，均可通过 `--config=<ini>` 由 `ParamRegistry` 注入超参。

### 6.1 监督预训练（`--mode=supervised`）

用模拟数据（`MockDataGenerator`）构造 (状态, π, z) 样本，按策略交叉熵 + 价值 MSE 训练 CA-MOE，用于冷启动。

### 6.2 无监督自强化（`--mode=unsupervised`）

AlphaZero 主循环：

1. **自对弈**：`num_workers` 个并行 worker 用 HMGS-DP 生成对局；开局施加 **Dirichlet 噪声**（α、权重可配）增加探索，按 `temperature` 采样着法并随步数衰减；并行搜索使用**虚拟损失**。
2. **经验回放**：样本入 `ReplayBuffer`，支持**渐进式经验池扩张**（初始容量 → 最大容量，按间隔倍增），容量占满后按窗口淘汰旧样本。
3. **训练**：按批次采样，8 向对称数据增强，AdamW 优化，可选混合精度（AMP）+ 梯度裁剪；按间隔评估 ELO 与保存检查点。

### 6.3 二倍体分化竞争（`--mode=diploid`）

维护两个模型分支互相竞争，每代进行自对弈与竞争对弈，按 **ELO 门槛**（`elo_min_improvement`）决定是否接受新参数，未达标则回退至上一代，抑制棋力震荡。

### 6.4 ELO 门控在线训练（`--mode=elo-gated`）

面向单模型快速迭代，核心是"**严格改善才接受**"：

1. **对弈学习**：M（当前模型）与 Gen0 基线对弈若干局，逐局学习（一局一更新）。
2. **KataGo 评估标尺**：每轮与固定强度的 KataGo 对弈 1 局，以**目差**作为标尺值；若标尺值严格优于历史最佳则接受并保存，否则**回滚至轮初快照**并重建优化器。
3. **KataGo 教师蒸馏**：每轮生成若干局 KataGo 自对弈棋谱作为教师数据，对每局重复训练若干遍以复用学习信号。
4. **累积 ELO**：接受时累加固定增量，形成可跨基线延续的进度标尺（换基线时用 `--elo-cumulative-start` 延续）。

关键参数：`--elo-simulations`（搜索模拟数）、`--elo-lr`、`--elo-temperature`、`--elo-hidden`/`--elo-gen0-hidden`（模型通道宽度）、`--elo-katago-*`（KataGo 路径/强度/蒸馏规模）。

## 七、性能优化要点

1. **位棋盘 + 位运算**：气/连通块/合法着法以位操作完成。
2. **批量推理**：搜索按 batch 收集叶子节点统一前向，充分利用 GPU；批量大小取 2 的幂。
3. **DAG 状态合并**：换位表避免相同局面的重复评估。
4. **并行搜索**：多 worker + 工作窃取队列（`WorkStealingQueue`）+ 虚拟损失。
5. **异构分片**：拓扑等批量计算在 CPU 多线程与 GPU 间动态分片。
6. **混合精度（AMP）**：训练可选 FP16，配合梯度缩放（`amp_grad_scaler`）。
7. **渐进式经验池**：先用小池快速迭代，再随训练扩张，降低早期显存/内存压力。

## 八、关键公式汇总

| 名称 | 公式 |
|------|------|
| UCT 选择 | `UCT(i) = Q(i) + C · P(i) · √(ln N / n_i)` |
| 门控融合 | `w = softmax(W₂·relu(W₁x) + W_s·s)`，`y = Σ w_e·y_e` |
| 总损失 | `L = w_p·L_policy + w_v·L_value + w_g·L_gating` |
| 温度采样 | `p ∝ π^(1/τ)`，τ 随步数按 `temperature_decay` 衰减 |
| ELO 接受判据 | `标尺值 > 历史最佳` 则接受，否则回滚 |
