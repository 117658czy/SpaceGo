## 二、技术成果

### 2.1 HMGS-DP 搜索

- **并行 UCT**：多 worker + 工作窃取队列 + 虚拟损失，支持批量推理路径。
- **状态合并（DAG）**：以 Zobrist 换位表将相同局面合并为共享节点，避免重复神经网络评估；换位表统一持有节点所有权，规避 DAG 下的重复释放。
- **算法组件化**：`SearchEngine` 门面 + UCT/相似度/多样性计算、节点管理、合并网络、搜索控制、模拟执行、持久化等专职组件，支持搜索树/合并网络/多样性图的导出与导入（含 v1 兼容）。
- **多样性保护**：对长期未合并、久未访问的分支追加探索资源，抑制过早收敛。
- **空间拓扑加速**：`SpatialTopologyAccelerator` 批量计算拓扑特征，按规模在 CPU 多线程与 GPU 间分片。

### 2.2 CA-MOE 混合专家元决策

- 共享主干（10 残差块 / 256 通道）+ **8 组专家策略头与价值头** + 门控网络，融合输出策略与价值。
- **对手风格条件化**：5 维风格向量经零初始化投影叠加为门控偏置，使得"按对手棋风选择专家"成为可学习机制，且不破坏既有棋力（旧 checkpoint 兼容加载 `load_compat`）。
- **防门控坍缩**：基于实测教训固定 softmax 温度，改用 KL/负载均衡正则 + Dropout + logits L2。

### 2.3 CUDA 与异构计算

- 位棋盘（6×uint64）表示，批量 CUDA 内核覆盖合法着法、气、合法性校验、落子提子、特征平面生成，采用 SoA 布局与 2 的幂批量。
- 异构调度：工作负载分析 → 任务分解 → CPU/GPU 负载均衡（NVML 采样 + EMA 平滑，失败自动回退启发式）→ 结果合并，全程可降级运行。

### 2.4 训练体系

四种训练模式全部实现并跑通：

| 模式 | 关键机制 |
|------|---------|
| 监督预训练 | 模拟数据冷启动 |
| 无监督自强化 | 自对弈 + Dirichlet 噪声 + 经验回放 + 渐进式经验池扩张 + AMP |
| 二倍体分化竞争 | 双分支竞争 + ELO 门槛接受/回退 |
| ELO 门控在线训练 | 逐局学习 + KataGo 目差标尺 + 严格改善接受/回滚 + 教师蒸馏 + 累积 ELO |

配套工具：`ParamRegistry` 参数注册与配置文件加载、`CLITuner` 交互调参、`AutoTuner` 自拟合调参（试验历史与最优参数落盘）、训练日志与门控/梯度诊断输出。

### 2.5 工程成果

- **可配置构建**：CUDA / LibTorch / 训练 / GUI / 测试 均可独立开关，支持 Visual Studio 与 Ninja。
- **标准接口**：标准 GTP 协议，可直接对接 Sabaki、Lizzie 等前端。
- **图形界面**：Win32 + GDI+ 实现的三栏布局界面（对弈 / 学习 / 分析 / 设置），含伦勃朗光源棋子渲染、圆角控件、动画系统。
- **可维护性**：模块化目录、中文注释、构建产物与模型文件的 `.gitignore` 规范。

## 四、本次剔除的模块（开源裁剪）

以下模块经**依赖可达性分析**确认与引擎运行无关，已从开源版本移除：

| 模块 | 内容 | 剔除理由 |
|------|------|---------|
| 模块间通信子系统 | `network/core`（socket/连接/事件循环）、`network/bandwidth`、`network/interface`（websocket/REST/插件/负载均衡） | 引擎为进程内 GTP 模式，无网络通信需求 |
| 压缩加密 | `protocol/compression_encryption`（AES/miniz） | 仅被通信子系统使用 |
| 因果链推理 | `causal/*`（9 个子模块） | 未接入搜索与推理主链路 |
| 评估子系统 | `go/evaluation/*`（胜负率、复杂度、对手镜像等 10 个） | 未被引擎与训练入口引用 |
| 局面分析 | `go/analysis/position_analyzer` | 未被引用 |
| 引擎协调器 | `go/engine/{board_view,data_channel,engine_coordinator,pipeline_stage}` | 未被 `GoEngine` 使用 |
| 部分搜索/网络/训练代码 | `ca_moe_mixture`、`meta_decision_maker`、`topology_aware_uct`、`EnhancedNeuralNetwork`、`StyleAdaptedNN`、`HybridNeuralNetwork`、`rl_finetune` 等 | 实验性实现，未接入主链路 |
| 第三方库 | `third_party/{aes,miniz}` | 随压缩加密模块一并移除 |
| 死 CUDA 内核 | `go_board_kernels_optimized.cu`、`topology_kernels.cu` | 仅被已剔除模块调用 |

同时未纳入开源版本：构建产物、预编译可执行文件、模型权重、自对弈 SGF 棋谱、软件著作权申请材料、临时脚本与历史日志。

## 五、当前局限

1. **棋力有限**：ELO 门控训练的最优观测为对 KataGo 目差 -349.5 目，模型尚未形成有效棋形（详见 [训练日志总结](训练日志总结.md)）。
2. **门控坍缩尚未根治**：专家分化在部分运行中退化为固定权重。
3. **评估信号稀疏**：每轮 1 局评估导致标尺噪声大、回滚频繁。
4. **GUI 未接入引擎**：界面可独立构建运行，但尚未接入对弈引擎。
5. **目录命名历史遗留**：搜索算法核心位于 `network/algorithms`，与"网络通信"无关，已在 README 与贡献指南中说明（未重命名以避免大规模改动）。

### 5.1 已确认的搜索/推理缺陷（P0/P1）

| 级别 | 缺陷 | 代码位置 | 影响 |
|------|------|---------|------|
| P0 | 批量收集按 `batch_size` 消耗迭代预算，同一批内重复选中同一叶子 | `src/go/search/hmgs_dp_optimized.cpp` 搜索主循环 | `--simulations=800` 仅约 6–7 次有效展开 |
| P0 | UCT 直接最大化子节点视角价值，父节点未取反 | 同上 `select_node_for_expansion()` | 选择方向错误 |
| P0 | 白方价值翻转条件写作 `current_player == -1`，而 `StoneColor::WHITE == 2` | `src/decision/engine/go_engine.cpp` 价值/批量回调 | 白方价值未翻转 |
| P1 | `genmove` 返回 pass 时未切换行棋方或累加连续 pass | `src/decision/engine/go_engine.cpp` `genmove_with_time` | 连续两 pass 无法终局 |
| P1 | `boardsize` 接受 9/13，但坐标/编码/策略索引按 19 路硬编码 | `go_board_cuda.cpp`、`go_engine.cpp`、`gtp_protocol.cpp` | 非 19 路对局错位 |
| P1 | CUDA 棋盘内核对气数/合法性为占位实现 | `src/perception/cuda/go_board_kernels.cu` | GPU 批量棋盘计算不可用于实战 |
| P2 | 17 通道输入仅填充 3 个平面 | `encode_to_tensor()` | 输入表达力受限（训练/推理一致） |

> 这些问题不影响“架构与训练闭环已跑通”的结论，但会直接影响棋力与基准可信度。
> 修复顺序与验收标准见 README 的“路线图与贡献方向”。

## 六、后续方向

1. 扩充并清洗自对弈数据，延长连续训练而非频繁回滚。
2. 增加每轮评估局数、引入胜率与目差双指标，降低门控噪声。
3. 监控专家使用熵，强化负载均衡正则，根治门控坍缩。
4. 将 GUI 接入引擎（通过 GTP 子进程或直接调用引擎接口）。
5. 在目标硬件上建立性能基准（搜索节点/秒、GPU 利用率）。
